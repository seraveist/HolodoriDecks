# Holodori DeckSim

홀로라이브 드림스의 라이브 편성을 구성하고 결과를 확인하기 위한 개인용 정적 웹 프로젝트입니다.

현재 버전은 첨부된 `holodori_deck_prototype_v03.zip`의 계산 흐름을 기준으로 **멤버 프리셋 → 악곡 세팅 → 계산 실행 → TOP 5 순위 결과**를 정적 웹에 연결합니다.

## 현재 제공 기능

- 라이트 모드 기반 단일 페이지 UI
- 시뮬레이션 목표 선택: 최고 유닛 스코어 / 최고 잠재 스코어
- 현재 레벨/MAX 육성 기준과 TOP 5 고정 추천
- 리더와 같은 홀로멤의 멤버 카드 제외 여부 설정
- 리더 1명 + 멤버 5명 편성과 프리셋 슬롯의 현재 레벨·개화 표시
- 데스크톱 5열 카드와 미보유 회색 이미지로 구분되는 내 보유 카드 리스트
- ★5→★4, 각 희귀도 안에서는 최신 데이터순인 기본 정렬과 인게임 캐릭터순 선택지
- 보유 카드별 레벨·개화를 브라우저에 저장
- 보유 카드 ID·레벨·개화를 JSON으로 내보내고 가져오기
- 보유 카드만 표시하는 슬롯 클릭형 카드 선택 팝업
- 사용자가 선택한 리더·멤버 슬롯을 고정 프리셋으로 유지
- 비어 있는 프리셋 슬롯을 채운 추천 결과만 생성하고 프리셋 자체는 변경하지 않음
- 모든 보유 카드를 리더·멤버 후보로 사용하고 리더 조건을 만족하는 편성을 선택한 스코어 목표 순으로 추천
- 원본 비율을 유지한 16:9 카드 선택 목록
- 보유 목록과 카드 선택창에서 여는 카드 파라미터·스킬·리더 효과 상세 정보
- 카드 이름/캐릭터 검색, 희귀도·타입 필터, 정렬
- 악곡 이름·난이도·AUTO/Manual FC 기준 선택
- 헤더와 가로형 6카드까지 접기 영역으로 사용하고, 펼치면 점수 산식과 리더 조건 배지·발동 주기·충돌·패시브 상태·팀 전체 발동 구간을 표시하며 멤버명 호버로 스킬 정보를 확인하는 순위 결과 카드
- GitHub Pages 하위 경로에서도 동작하는 상대경로 로딩

## 정적 웹 구조

```text
index.html
styles.css
css/
  tokens.css
  base.css
  components.css
  owned.css
  modal.css
  responsive.css
js/
  app.js
  data.js
  recommend.js
  score.js
  state.js
  ui/
    cards.js
    member.js
    modal.js
    music.js
    owned.js
    result.js
    target.js
data/generated/
  cards.json
  music.json
assets/
  cards/{card.id}.webp
  ui/
```

브라우저는 `js/data.js`에서 먼저 `data/generated/manifest.json`을 읽고, 같은 동기화 버전의 `cards.json`, `characters.json`, `music.json`을 정적 파일로 읽습니다. manifest의 카드·캐릭터·악곡 개수와 실제 JSON이 다르면 이전 데이터가 섞인 것으로 판단해 실행을 중단합니다. 별도 API나 백엔드는 사용하지 않습니다.

보유 카드, 카드별 현재 레벨·개화와 고정 프리셋은 `localStorage`에 저장되어 같은 브라우저에서 새로고침해도 유지됩니다. 서버나 계정에 동기화되는 정보는 아닙니다.

## 이미지 정책

- ★4/★5 카드: `assets/cards/{card.id}.webp`
- ★3 카드: 동기화 데이터에는 유지하되 보유 카드·프리셋 선택 목록에서는 제외
- 악곡: 썸네일을 사용하지 않음
- UI 타입 아이콘: `assets/ui/`의 프로젝트 SVG 사용

현재 마스터에는 카드 169장, 악곡 182곡, 플레이어블 캐릭터 62명이 포함되어 있습니다. ★4/★5 카드 이미지 115장도 모두 준비되어 있습니다.

## 로컬 테스트

HTML 모듈과 `fetch()`를 사용하므로 파일을 직접 더블클릭하지 말고 간단한 로컬 웹 서버로 실행합니다.

```bash
python -m http.server 8000
```

저장소 폴더에서 위 명령을 실행한 뒤 브라우저에서 `http://localhost:8000/`을 엽니다. 이전 ZIP을 사용한 폴더에 덮어쓰지 말고 새 빈 폴더에 압축을 해제해야 합니다. 자세한 내용은 [LOCAL_TEST.md](LOCAL_TEST.md)를 참고하세요.

정적 웹 호환성 검사는 별도 설치 없이 Node.js로 실행할 수 있습니다.

```bash
node scripts/validate-static.mjs
```

Python 동기화 계층까지 포함한 전체 검증은 다음과 같습니다.

```bash
python -m pip install -e . pytest
pytest
```

## GitHub Pages

`.github/workflows/pages.yml`은 `main` 브랜치가 갱신될 때 정적 웹에 필요한 파일만 Pages 산출물로 묶어 배포합니다. 저장소의 **Settings → Pages → Source**는 `GitHub Actions`로 설정합니다.

모든 경로는 저장소 하위 URL에서도 동작하도록 상대경로로 구성되어 있습니다.

## Master-data sync

기존 master-data sync는 그대로 유지합니다. `.github/workflows/sync-master-data.yml`이 매일 **00:00 KST**에 `HolodoriDB/holodori-db-kor-diff`의 참조 파일 변화를 확인합니다.

- 참조 파일이 같으면 정규화를 건너뜀
- 변경된 경우 하나의 upstream commit에 고정해 데이터 재생성
- 카드/악곡 스키마와 리소스 호환성을 검증한 뒤 변경분만 커밋
- 동기화 직후 새 manifest와 카드·캐릭터·악곡 JSON의 웹 호환성을 다시 검증
- `workflow_dispatch`로 수동 실행 가능

## 계산 엔진 상태

추천 계산은 첨부 프로토타입의 유닛 스코어 계산을 확장한 `Unit Score Engine v0.4-potential`과 `Song Score Engine v0.3` 구조, 경험 상수 `K=2.037342`를 사용합니다. 직접 선택한 리더·멤버 슬롯은 계산 조건으로만 고정하며, 계산 후에도 프리셋 슬롯을 추천 카드로 덮어쓰지 않습니다.

- 자동 리더·멤버 후보: 등록한 모든 보유 카드 사용
- 리더 기본 조건: 항상 하드 제약으로 적용하며 불충족 편성은 순위 대상에서 제외
- 최고 유닛 스코어: 전체 평균에서는 기대 발동률을 반영한 유닛 스코어, 곡 지정 시에는 선택 악곡의 예상 평균 스코어 내림차순
- 최고 잠재 스코어: 전체 평균에서는 모든 유효 액티브 성공을 가정한 잠재 유닛 스코어, 곡 지정 시에는 선택 악곡의 근사 최대 스코어 내림차순
- P/T/S는 최적화 목표가 아니라 결과 상세의 파라미터 지표로 표시
- 결과 개수: TOP 5 고정

`최고 유닛 스코어`는 실제 발동 확률과 기대 가동률을 반영한 편성을 우선합니다. `최고 잠재 스코어`는 같은 조건에서 모든 유효 액티브가 성공한다고 가정했을 때 고점이 가장 높은 편성을 우선하므로, 기대 스코어가 다소 낮아도 잠재 최대값이 높은 별도 편성이 추천될 수 있습니다.

악곡 지정 시 곡 길이·난이도별 추정 노트 수·스코어 계수와 각 액티브 스킬 주기를 반영합니다. 동일한 액티브 주기는 발동 구간 중첩을 별도로 보정합니다. AUTO는 콤보 보너스를 제외하고, Manual FC 근사는 집계 노트 기반 콤보 보너스를 포함합니다.

프로토타입 규모처럼 계산 후보가 제한적일 때는 가능한 조합을 전부 평가합니다. 보유 카드가 매우 많아 전체 탐색이 브라우저에 과도한 경우에는 목표별 후보 탐색과 보조 휴리스틱을 합친 고속 모드로 전환하며, 결과 상태에 탐색 방식을 표시합니다.

개화 단계는 초기 프로토타입과 같이 1개화 Active Lv2, 2개화 전체 파라미터 +10%, 3개화 Special Lv2, 4개화 Passive Lv2를 적용합니다. 현재 `music.json`에는 실제 노트 타임라인이 없으므로 곡별 점수는 집계 채보 근사이며 실제 플레이 최대값을 보장하지 않습니다. 계정별 Holo멤버 보드·메모리 보정은 포함하지 않습니다.
